# Database migrations (owner: Asif)

Hand-written Alembic migrations. RLS policies, grants and triggers can't be autogenerated, so there is no model metadata here. **Only Asif writes migrations**; need a column? Ask (guide §1.2). Never edit a migration that is already on `main`; add a new one.

| Revision | What |
| :--- | :--- |
| `001_core` | Core tables (backend-plan §4): banks, users, sessions, auth_tokens, invitations, cases, documents, document_contents, ai_extractions, notes, audit_log |
| `002_rls` | Row-level security on every table (`FORCE`), least-privilege grants to `app_user` (no `DELETE` anywhere), append-only `audit_log` trigger, `next_case_reference()` (sequence starts at 100) |
| `003_chat` | Bluebooks, `vector(768)` passages, transcript/feedback storage; forced RLS, published victim-facing knowledge only, case/bank foreign keys |

Before migration 003, a database administrator must run `CREATE EXTENSION IF NOT EXISTS vector;`
in both the application and test databases. The migrator stays non-superuser. Use a pgvector-enabled
Postgres distribution; ordinary Postgres without the extension fails with an explicit setup message.
Downgrades preserve the extension. See [Asif's handoff](../../contributors/asif/REMAINING_WORK.md).

### The scope every query needs (002)

Policies read three transaction-local settings, set by `app/db.py` at the start of every transaction:

| Setting | Values |
| :--- | :--- |
| `app.role` | `operator`, `supervisor` (all banks) · `bank_viewer` (own bank, read-only) · `victim` (own cases) · `system` (auth tables, seed, background jobs) |
| `app.user_id` | the caller's `users.id`, or empty |
| `app.bank_id` | the bank viewer's bank, or empty |

No scope, or an unknown role, sees **no rows**. The seed must run with `app.role = 'system'`, because `FORCE ROW LEVEL SECURITY` applies to the table owner too. Set `APP_DB_ROLE` before migrating if the app's database user isn't called `app_user`.

## First time (local Postgres 16)

```bash
psql -h localhost -U postgres -f backend/scripts/bootstrap_db.sql   # creates migrator, app_user, fraud_relief, fraud_relief_test
```

On a hosted Postgres, create the `migrator` and `app_user` roles in the provider's console instead.

## Run

```bash
cd backend
export MIGRATIONS_DATABASE_URL=postgresql+psycopg://migrator:migrator_password@localhost:5432/fraud_relief
uv run alembic upgrade head      # or: alembic downgrade -1
uv run alembic current
```

Until `pyproject.toml` exists, prefix commands with
`uv run --no-project --with alembic --with sqlalchemy --with "psycopg[binary]" --with pytest`.

## Database-rule tests

Raw SQL as `app_user`, never as a superuser (superusers skip RLS). Each run migrates the test database to base and back to head.

```bash
cd backend
export TEST_MIGRATIONS_DATABASE_URL=postgresql+psycopg://migrator:migrator_password@localhost:5432/fraud_relief_test
export TEST_DATABASE_URL=postgresql+psycopg://app_user:app_password@localhost:5432/fraud_relief_test
uv run python -m pytest tests/database -q
```

The tests refuse to run unless the database name ends in `_test`.
